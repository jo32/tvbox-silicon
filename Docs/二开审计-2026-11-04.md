## 一、本轮已修（有代码改动）

### 1. 「跳过片尾」永远不会出现
`App/MobilePlayer.swift` · `loadSkipSegment()`

解析只在 `.task(id: clock.item)` 里跑一次，而那一刻 `clock.duration` 还是 0。片尾段是从**末尾**
倒推的（`duration - outroLength`），前置判断 `duration > settings.outroLength` 直接把它拦掉，
之后再没有任何重算时机 —— 所以手动标记的片尾标记只写进存储，按钮永远不出现。

修：新增 `.onChange(of: clock.duration > 0)`，时长第一次到手时重新解析一次。

### 2. 「按实测画质排序」四个属性只有分辨率真的生效
`Sources/TVCore/ResourceRanking.swift` · `Candidate(_:)`；`App/Store.swift` · `rankSourcesByMeasuredQuality()`

`Candidate` 从探针构造时把 `bitrateBitsPerSecond` 写死成 nil（这个判断本身是对的：吞吐量不等于
码率），`fileSizeBytes` / `isHDR` 调用点也没传。于是排序页上「视频码率 / 文件大小 / 色彩范围」
三行、以及「速度优先」预设（只由码率+体积组成），选了等于什么都没变。

而且这一层语义本来就错位：一个**源**不是**文件**，文件大小和 HDR 是单个文件的属性，测速扫不到的。

修：`ResourceRanking.Key.Attribute.speedTestProvides`（只有分辨率 true）；排序页对没有数据的属性
显示「暂无数据」而不是给一个能按的方向选择，footer 明说现在只有分辨率会改变结果。

### 3. 删掉的聚合订阅，下次启动又回来了
`App/Store.swift` · `seedAggregatedSubscriptions()`

启动时把缺失的三个聚合地址重新导入，不区分「从没有过」和「用户删了」。删掉 124.223 源或本机
Rex 源后，每次启动都复活，看起来像删除失败。

修：记住被删地址（`dismissedAggregateSubscriptions`），启动时跳过；手动再加回来时清掉记录。

### 4. 切后台遮罩淡入，截图时是半透明的
`App/PrivacyShade.swift`

遮罩用 0.12 s 动画淡入，而系统在进入后台的瞬间就截窗口快照 —— 这正是它要挡的那一帧。
修：出现不带动画（`covered ? nil : .easeOut(...)`），返回前台时才淡出。

### 5. 手机没有语音识别模型时，播放器里那一项直接消失
`App/MobilePlayer.swift` · 选项菜单

`speechLanguage` 为 nil 时整项不渲染，用户只会觉得「这版没有这个功能」，而真相是本机没有
对应语言的模型。修：给一条禁用的「本机没有语音识别模型」项，说明原因。

## 二、定位到了、本轮没修（要么改动大，要么要有真机才能验）

### 6. 语音字幕对「需要 Referer 的源」必然失败（高）
`Sources/TVCore/SpeechSubtitles.swift` · `transcribe(asset:language:name:hint:progress:)`

识别请求直接吃 `(asset as? AVURLAsset)?.url`，识别器**自己重新下载**这个地址，播放器 asset 上挂的
`AVURLAssetHTTPHeaderFieldsKey` 带不过去。凡是靠 Referer 防盗链的源，识别阶段拿到的是 403 响应体，
结果就是「没有识别出内容」或直接失败。另外 asset 不是 `AVURLAsset` 时会回落到
`URL(fileURLWithPath: "/dev/null")`，同样必败。

附带两个小问题：`progress` 只有 0 和 1，界面上的百分比是装饰；`SFSpeechURLRecognitionRequest`
单次能吃的音频有限（约一分钟量级），一集 45 分钟必然中途结束，`shouldReportPartialResults = false`
+ 只接受 `isFinal` 就更拿不到结果。

建议改法：先把音轨连同 headers 落到临时文件（AVAssetReader / AVAssetExportSession 都行），再按
2 分钟切片分别识别，最后按 `CMTimeRange` 偏移合并 —— 这样 headers、长片、进度三件事一起解决。

### 7. 「修复失效线路」只修第一条视频，且会虚报条数（中）
`App/Store.swift` · `batchFixUnreachableLines(_:)`

* 只看 `page.videos.first`：某个源里除首页第一条以外的死链永远不会被修。
* `.proxy` 分支在没有自定义代理时什么都不做，但仍然 `touched += 1`，界面报「已修复 N 条」是假的。
* 每个源都要重新拉一次首页（N 次网络），而测速结果里其实已经有线路信息。

建议：先修 `.proxy` 无代理时改报「没有可用的代理」并跳过计数；遍历改为「首页 + 已知有死链的视频」，
或者干脆只按已测速记录批量下发，不再重复请求。

### 8. 第三个聚合源写死了开发机主机名（中）
`App/Store.swift` · `aggregatedSubscriptionAddresses`

`http://macdemacbook-pro.local:8081/api/rex/movie-degraded.json` 只在你这台 Mac 的局域网里能解析。
换设备、换网络都是 DNS 失败，于是每次启动都白跑一次导入、并置一条 `importError`。

建议：只在「本机就是那台 Mac」（同一局域网 HTTP 探测成功）时才纳入播种列表，或者把它从
`aggregatedSubscriptionAddresses` 里挪出、改为设置里手动添加。

### 9. 资源排序页的「速度优先」预设仍然可点，但不会改变顺序
与 #2 同源。现在 footer 已说明，但预设按钮本身没有置灰 —— 后续要么隐藏该预设，要么等
逐资源（而不是逐源）排序接上后再开放。

### 10. 折叠屏方向状态是静态变量，没有随播放器释放复位（低）
`App/PlayerView.swift` · `PlayerOrientation`

`holdsPortrait` 是 `static`，只在 `SitesView` 的 `onDisappear` 里复位。如果页面在
`duoExpanded == true` 状态下消失（折叠态直接杀掉页面、或外接屏切换），下一次启动播放器时
`restore()` 的行为会继承上一次的握持状态。`release()` 里补一行 `holdsPortrait = false` 更稳。

## 三、复核过、确认不是 bug 的几处

* `ResourceRanking.sort` 的缺失值处理：`nil` 一律排在「有值」之后，和方向无关 —— 所以「没测过的源
  排最后」这句提示是真的。
* `rankSourcesByMeasuredQuality` 把内置源放列表最前：显示是按订阅分组的，组内顺序才是它影响的，
  跨组不受影响。
* `ImageLoadGate` 在滚动时是**等待**（上限 48 个等待者）而不是丢弃，`PosterLoader` 的
  `begin/finish` 在成功与异常路径上成对，不会泄漏配额。
* 保险箱过滤管道（`permits(site:fallback:)`）用源自身的 origin 判断订阅级隐藏，内置源不受
  「隐藏了某个订阅」波及 —— 之前那版 bug 确实修掉了。
