# 真机验收（iPhone Duo）

模拟器上的截图只能证明「界面画出来了」，证明不了「装到手机上还能用」。这份文档记录真机这条路怎么走、
哪些已经验证过、哪些还缺物理条件。

## 一条命令

```bash
Scripts/test-duo-ui.sh                    # 真机
Scripts/test-duo-ui.sh --simulator <UDID> # 模拟器，同一套用例
```

它做四件事：生成一个只含「占位宿主 + UI 测试 bundle」的临时工程 → 用 Duo 证书那套签名（模拟器则免签名）
→ 在设备上跑 `XCUITest` → 把每屏截图导到 `build/DuoUI/shots/`。

产物：

| 路径 | 内容 |
|---|---|
| `build/DuoUI/shots/*.png` | 每屏一张，按用例里的名字命名 |
| `build/DuoUI/result.xcresult` | 完整结果，失败时留着日志和截图 |
| `build/DuoUI/test.log` | `xcodebuild` 原始输出 |

只跑一屏：

```bash
Scripts/test-duo-ui.sh -only-testing:DuoUITests/DuoAcceptanceUITests/testSettingsShowsVersion
```

**先在模拟器上跑**。模拟器不需要数据线、不受息屏影响，能先证明用例本身是对的；等真机条件齐了再跑真机，
出问题时就知道是设备环境而不是断言写错了。

## 前置条件

1. **数据线**。这一条最容易被忽略，见下一节。
2. 手机解锁、屏幕亮着。息屏状态下截出来的图是全黑的，用例里的 `launch()` 也点不动界面。
3. 「设置 → 隐私与安全性 → 开发者模式」为开。`devicectl device info details` 里能看到
   `developerModeStatus = enabled`。
4. 证书目录 `~/Documents/windows11/编程工具/mac/证书/Duo 证书/`：`ios_development.p12`（口令 `1`）
   + `all1023.mobileprovision`。描述文件是通配 App ID `G4XMHC9NWZ.wda.prdc.*`，所以测试运行器
   `wda.prdc.qaui.tests.xctrunner` 也能签。

## 为什么必须插线

2026-11-04 实测：设备通过**无线**连上来时（`transportType = localNetwork`），装 App 能成、测试运行器
能装也能自己跑完用例，但 `xcodebuild` 连不上它：

```
DuoUITests-Runner (7438) encountered an error (Early unexpected exit, operation never finished
bootstrapping. Underlying Error: The test runner exited with code 74 before establishing connection.)
Connection peer refused channel request for "dtxproxy:XCTestDriverInterface:XCTestManager_IDEInterface"
```

拆分验证过，两层都是好的：

- `xcrun devicectl device install app` → `App installed`，`devicectl device process launch` → 进程起来、无崩溃。
- 手动 `devicectl device process launch --console wda.prdc.qaui.tests.xctrunner`，运行器自己跑完
  `Executed 2 tests, with 0 failures`，退出码 0。

所以坏在中间那根 DTX 会话上，而它在无线连接下建不起来。脚本会提前识别并拦下（退出码 5），
不会让你等一轮构建才看到 code 74。确实想试无线：

```bash
DUO_ALLOW_WIRELESS=1 Scripts/test-duo-ui.sh
```

## 用例清单

| 用例 | 验的是什么 |
|---|---|
| `testEverySectionOpens` | 八个核心分区逐个启动，断言该分区自己的 `section.<标题>` 标记出现，再截图 |
| `testSourcesListsSubscriptions` | 点播源页有 `sources.group.*` 订阅分组（用户反馈的「看不到订阅资产」就是这里空了） |
| `testSettingsShowsVersion` | 设置页显示 1.8.x，证明测的是刚装的那个包而不是旧副本 |
| `testPrivacyVaultDraws` | 隐私保险箱画出来了：设置密码入口、密码框、解锁键盘三者之一存在 |

分区只挑八个而不是十二个。每次启动都是一个带着 JVM、Python、JS 三个运行时的全新进程，
连着十二次会让测试运行器自己累死 —— 报 `Restarting after unexpected exit, crash, or test timeout`，
屏幕列表没错，是夹具撑不住。现在每屏拍完就 `terminate()`，八屏跑完 130 秒。

这些用例只读：走到某一屏、断言、拍照。不点开关、不删数据、不调顺序 —— 跑的是用户自己的订阅和设置。

系统弹窗（通知、后台定位、"在 xx 中打开?"）属于 SpringBoard，会盖在所有界面之上。`dismissSystemAlerts()`
在每次启动前后各扫一遍，优先点「允许」，让权限一次过、下次不再弹。

## 假通过是怎么抓出来的（2026-11-04）

第一轮八屏全绿，但逐张看图发现有两屏拍错了页：`-qaSection favorites` 拍到的是「现在观看」，`-qaSection downloads` 拍到的是「设置」。
原因是断言只问「窗口在不在」——首页永远在，于是错屏也能过；截图之间只靠时钟秒针区分，指纹校验也放行。

两处改动：

1. **分区自带标记**。`App/RootView.swift` 的 `content(_:)` 给每个分区根页面加
   `accessibilityIdentifier("section.<AppSection 标题>")`（如 `section.Downloads`、`section.Sources`），
   新增分区不用改测试，标题自动生效。
2. **断言改成认标记**。`testEverySectionOpens` 用 `waitForExistence(timeout: 30)` 等自己那一屏的标记，
   等不到就失败并说出是哪一屏。截图前的固定 `sleep(2)` 保留，只是为了让画面稳定，不再承担判据。

顺带解释了为什么之前看着像「深链没生效」：XCUITest 下 App 带调试器启动比 `simctl launch` 慢，
2 秒时分区还在落地，于是拍到首页。等待标记后八屏 97 秒跑完（原来 180 秒），每屏都是对的。

**断言真的会失败**：反向跑一次「打开收藏页、断言它是下载页」的探针，8 秒后失败
（`XCTAssertTrue failed - 负向用例：收藏页不该被认成下载页`）。探针不进仓库（它本来就该红），
要复现就照这个形状写一个：`XCUIApplication(bundleIdentifier:)` + `-qaSection favorites` +
断言 `section.Downloads` 存在，用 `Scripts/test-duo-ui.sh --simulator <UDID> --tests <该文件>` 跑。

## 截至 2026-11-04 的实测状态

- **装机**：`Scripts/install-duo.sh` 在本机跑通 —— 构建、签名、安装、启动全部成功，
  `App installed` + `Launched application`，设备上进程存活、无崩溃报告。
- **模拟器验收（已全绿）**：`Scripts/test-duo-ui.sh --simulator 08DE0FEC-…`（iPhone 17 Pro，iOS 26.5）
  在 HEAD `f9413bf` 上 4 个用例全过，八屏截图逐张核对无误：现在观看 / 发现 / 直播 / 点播源 /
  收藏 / 下载 / 设置 / 更多，另有隐私保险箱一屏。截图落在 `build/DuoUI/shots/`。
- **真机 UI 验收**：仍未完成，卡在两件物理条件 —— 无线连接建不起 XCTestDriver 的 DTX 会话（见上一节），
  且 `devicectl` 没有点击能力。插线 + 亮屏后 `Scripts/test-duo-ui.sh` 真机模式即可复用同一套断言。

## 顺带修掉的一个坑

`Scripts/install-duo.sh` 原来只认 `available (paired)` 状态的设备，而设备有时报 `connected`，
会被当成「没有可用真机」。现在两种状态都认，且**优先挑描述文件授权的那台** —— 插两台手机时，
挑错那台一定装不上。

## 无线也能截图：Scripts/shoot-duo.sh

UI 自动化要 USB，但设备平时是无线连的。这个脚本只做「带 `-qaSection` 启动 + `devicectl` 截图」，
无线可用，覆盖八个分区加隐私箱，产物落在 `build/DuoUI/live/<时间戳>/`。

息屏时 `devicectl` 照样能截，截出来全黑，看着像 App 白屏 —— 脚本先试拍一张判亮度，黑了就直接说明并
退出，不留一堆黑图。

两个坑记在这里：`devicectl device process launch` 传 App 参数**必须用 `--` 隔开**，否则 `-qaSection`
会被当成它自己的选项（报 `'sites' is invalid for '-t <seconds>'`）；`PlistBuddy` 读 `/dev/stdin` 会挂住，
解出来的描述文件要先落盘。

## 分屏布局（Duo 展开态）为什么还没验

`SitesView` 的左右分屏走 `splits`，两个入口：手机横屏（`landscapePage`）和 Duo 展开（`duoExpanded`）。
两条路现在都验不了，原因不同：

**模拟器**：`iPhone Duo` 这个机型在 Xcode 里是有的，但它的 `profile.plist` 写着
`minRuntimeVersion = 27.1`，而本机只装了 iOS 26.5 和 27.0 的模拟器运行时 —— 建就报 `Incompatible device`。
`xcodebuild -downloadPlatform iOS -buildVersion 27.1` 跑了 7 分半没有任何字节落下
（`~/Library/Caches/com.apple.dt.Xcode` 始终 3.8M），是网络这步不通，不是命令用错。

**手机横屏**：走不通，而且不是环境问题。`watchBody` 出现时会执行
`PlayerOrientation.holdPortrait(true)`（`App/SitesView.swift`），于是 App 立刻请求转回竖屏。
在 UI 测试里把设备转成 `landscapeLeft`，旋转请求和 App 的锁定相互拉扯，测试等到超时，运行器报
`Restarting after unexpected exit, crash, or test timeout`。同一个旋转动作在**点播源页**（不锁竖屏）
是能成功截图的，所以问题出在播放页的锁，不是旋转本身。

也就是说：`landscapePage` 分支在 iPhone 上只在「横着点进视频」的瞬间成立，随即被拉回竖屏；
这条布局真正稳定存在的场景就是 **Duo 展开态** —— `if !duoExpanded` 才锁竖屏，展开时不锁。

结论：这一项只能等真机上把手机展开来看。别在模拟器上再试，也别用旋转去凑 —— 试过了，见上。
