## 三、新增 P1（必须修，第一轮未覆盖）

### P1-1 `importConfig` 双向失效
`App/Store.swift:584-641` · 逻辑错误
- 新增订阅收进 `added[]` 后从未 append 进 `subscriptions`，重构只重排已存在条目 → 提示「Imported N」实际什么都没加。
- 「移除不在备份中的订阅」只删 documents/磁盘，没从 `subscriptions` 数组删，随后又被追加回末尾，且被 `needFetch` 当「缺内容」重拉 → 「restore 是权威」语义失效。
- 修：以 `incoming` 为准重建列表（已存在用现有 entry，不存在用 `synced.entry`），不再追加 removed。

### P1-2 SourceRouting relay 地址丢端口/query/https
`Sources/TVCore/SourceRouting.swift:119-125` · 逻辑错误
- `relayedAddress` 只用 `url.host()`+`url.path`，端口、query、https 全丢。`124.223.214.31:55316/9981` relay 后端口没了；`api.php?id=1` 的 `?id=1` 没了；https 降级 http。反向 `directAddress` 用 `hasPrefix("https")` 判断而 relay 恒 http → 切 Proxy→Direct 地址损坏。
- 修：relay 地址编码 scheme/host/port/path/query，direct 对称还原。

### P1-3 SourceProbe 取消被误记 unreachable
`Sources/TVCore/SourceProbe.swift:383-385` + `App/EpisodePicker.swift:70-72` · 逻辑错误
- `probe` catch 吞掉所有错误（含 `URLError(.cancelled)`）返回 `.unreachable` 落盘。切线路/关弹层取消的任务被记成「不可达」，污染 5 分钟缓存 + 排序。
- 修：区分 cancelled（返回 `.unknown` 或抛出），调用方 `guard !Task.isCancelled` 再落盘。

### P1-4 线路退避/冷却状态机从未接线
`Sources/TVCore/SourceProbe.swift:170-217` + `App/EpisodePicker.swift:78-85,274,333-340` · 集成缺失
- `declareBases/beginBase/succeedBase/failBase/cancelBase/availableBases/rankedBases` 全仓无调用方，`rotation.states` 恒空。冷却倒计时、「所有线路都在冷却」是死 UI；失败线路无退避立即重试。另有键粒度错位：picker 传线路 flag，HostRotation 按 host 键控。
- 修：probeIfNeeded 用 host 调 begin/fail/succeed，picker 按同一 host 查询；或删掉死 UI。

### P1-5 PrivacyVault「更改密码」完全失效
`App/PrivacyVaultView.swift:245,210-213` · 逻辑错误
- `Change Passcode` 只把 gated 设为 `.confirmCurrent`，验证成功后没有进 `.setNew` 流程；`setPasscode(_:replacing:)` 只挂在 `!hasPasscode` 分支。
- 修：confirmCurrent 成功后切 `.setNew` 并传 `replacing: 当前密码`。

### P1-6 CustomProxyTunnel 二次 resume 崩溃
`Sources/TVCore/CustomProxy.swift:69-84,194-204` · 崩溃
- `open()` 用 `withCheckedThrowingContinuation`，`stateUpdateHandler` resume 后未清除，`.failed/.cancelled` 再触发二次 resume → CheckedContinuation 直接 crash。
- 修：resume 前 `stateUpdateHandler = nil` 或用一次性 `hasCompleted` 标志。

### P1-7 SitesView split 布局黑背景铺满详情列
`App/SitesView.swift:2283,2287-2293,2309` · UI 逻辑
- split 态 `playerHeight = containerHeight`，`.background { Color.black.frame(height: playerHeight) }` 未约束宽度 → 铺满整页宽×高，右侧详情列（简介/选集）压纯黑底。浅色模式黑字落黑底不可读。
- 修：黑背景只在播放器列生效，或给详情 ScrollView 补 `.screenBackdrop()`。

### P1-8 macOS 播放器「Episodes」变死按钮
`App/CatalogPlaybackActions.swift:18,31` + `App/PlayerView.swift:280,1180` · 上游冲突
- 二开把二级选集菜单替换成 `Button(action: openEpisodes)`，但 `openEpisodes` 默认 `{}`，只有 iOS 全屏（MobilePlayer:935）传了；macOS 两个调用点都没传 → 点「Episodes」无反应，上游原有选集功能被删且未接回。
- 修：macOS 调用点也接 `openEpisodes`（弹选集 sheet），或非 iOS 保留旧二级菜单。

### P1-9 URL 导入订阅冷启动竞态静默丢
`App/TVBoxApp.swift:84-98` + `App/Store.swift:454-455,509-512` · 边界
- 冷启动 `yingxia://subscribe?url=` 的导入 Task 与启动 `.task` 的 `seedAggregatedSubscriptions/refreshSubscriptions` 并发，两者置 `importing=true`。URL 导入落进窗口时 `guard !importing else { return }` 直接返回，订阅静默丢弃无报错。全新安装（聚合源缺失、最需要 URL 导入）几乎必现。
- 修：导入排队等 `importing` 释放，或先处理 URL 导入再做 seeding。
